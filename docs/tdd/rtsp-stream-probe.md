# Task 3 — rtsp-stream-probe

## Raw request

Определить кодек, разрешение и fps источника RTSP и решить, нужен ли транскод.

## Spec

### Facts

- Проект greenfield. Python 3.14.4, тесты — `.venv/bin/pytest`.
- **Кодек камеры из §7 неизвестен и установить его не удалось**: `DESCRIBE`
  возвращает `401`, SDP получить не вышло. Именно поэтому кодек определяется
  в рантайме, а не задаётся константой.
- H.265/HEVC браузеры в HLS в общем случае не воспроизводят → при таком источнике
  транскод обязателен.
- При `-c copy` резать сегменты можно только по существующим keyframe источника,
  поэтому `hls_time` становится нижней границей [UNVERIFIED против первоисточника,
  но согласованно сообщается].

### Decisions (связывают эту задачу)

- **D8** — кодек определяется на старте: H.264 → `-c copy`, иначе → транскод
  в H.264. Результат этой задачи — тот самый булев флаг, который Task 1 принимает
  аргументом `transcode`.
- **D1** — источник параметризуется; проба должна работать с любым RTSP URL.

### Assumptions

- **[A1]** Используется `ffprobe -v quiet -print_format json -show_streams` (либо
  эквивалент), и его JSON разбирается. `ffprobe` есть в Docker-образе (D4).
- **[A2]** Из потока берётся **первый видеопоток** (`codec_type == "video"`).
  Аудио для этой задачи не рассматривается.
- **[A3]** `fps` в JSON приходит дробью вида `"25/1"` и требует разбора, а не
  прямого `float()`.

### Критерии готовности — чеклист, тестов не пишем

**Режим: без тестов** (решение D11). Проверяется одним прогоном против реальной
камеры: `ffprobe` уже подтверждён на ней вживую (H.264, 5120×1440, 20 fps).
Список ниже — чеклист, а не спецификация падающих тестов.

`src/ingest/probe.py`:

1. Есть неизменяемый `StreamInfo` с полями `video_codec`, `width`, `height`, `fps`.
2. Разбор зафиксированного образца JSON-вывода `ffprobe` для H.264-потока даёт
   правильные кодек, ширину, высоту и fps.
3. `fps` из `"25/1"` → `25.0`; из `"30000/1001"` → примерно `29.97`.
4. `needs_transcode(StreamInfo(video_codec="h264", …))` → `False`.
5. `needs_transcode(StreamInfo(video_codec="hevc", …))` → `True`.
6. `needs_transcode` для незнакомого кодека → `True` (осторожная сторона:
   лучше лишний транскод, чем чёрный экран).
7. JSON без единого видеопотока → понятное доменное исключение, **не** `KeyError`
   и не `IndexError`.
8. Ненулевой код возврата `ffprobe` → понятное доменное исключение с текстом
   stderr внутри.
9. Превышение таймаута → понятное доменное исключение.
10. **Тесты не запускают настоящий `ffprobe` и не ходят в сеть** — вызов
    подменяется.
