# Task 1 — hls-command-builder

## Raw request

Собрать argv для ffmpeg и вычислить стартовый номер сегмента так, чтобы перезапуск
ffmpeg не затирал историю DVR.

## Spec

### Facts

- Проект greenfield: кода, git-репозитория и манифестов зависимостей нет.
  Python 3.14.4, `uv` доступен. Тесты — `.venv/bin/pytest`.
- ffmpeg **в хосте не установлен**; по D4 он живёт в Docker-образе. Тесты этой
  задачи ffmpeg не запускают — проверяется только сборка списка аргументов.
- `-hls_playlist_type event` принудительно ставит `hls_list_size=0`; плейлист
  только дописывается [VERIFIED, ffmpeg `muxers.texi`].
- `hls_flags temp_file` пишет во временный файл и переименовывает по завершении;
  действует **и на сегменты, и на плейлисты** [VERIFIED, ffmpeg `muxers.texi`].
- `hls_flags append_list` дописывает в существующий плейлист и снимает
  `#EXT-X-ENDLIST` [VERIFIED, ffmpeg `muxers.texi`].
- `start_number`: «Default value is 0… if `hls_flags append_list` is set and read
  playlist sequence number is greater than the specified start sequence number,
  then that value will be used as start value» [VERIFIED, ffmpeg `muxers.texi`].
- У ffmpeg **нет автореконнекта для RTSP**: флаги `-reconnect*` документированы
  только для протокола `http` [VERIFIED, ffmpeg `protocols.texi`].

### Decisions (связывают эту задачу)

- **D6** — один EVENT-манифест: лайв и перемотка из одного источника. Поэтому
  `delete_segments` запрещён к появлению в argv при любых аргументах.
- **D5** — задержка измеряется по `EXT-X-PROGRAM-DATE-TIME`, поэтому флаг
  `program_date_time` обязателен всегда, а не опционален.
- **D8** — кодек определяется на старте; сюда он приходит булевым `transcode`.

### Assumptions

- **[A1]** Документированный автоподхват `start_number` при `append_list`
  **не сработает на EVENT-плейлисте**, потому что `EXT-X-MEDIA-SEQUENCE` у EVENT
  всегда остаётся 0 (первый сегмент никогда не вымывается), а условие в
  документации требует «greater than». Это **вывод из семантики RFC 8216 и текста
  ffmpeg, не эксперимент.** Поэтому `-start_number` передаётся явно — он корректен
  при любой из двух интерпретаций.
- **[A2]** Имена сегментов имеют вид `seg_%06d.ts`. Функция `next_start_number`
  разбирает именно этот шаблон.

### Acceptance criteria (форма падающих тестов)

`src/ingest/command.py`, тесты в `tests/test_command.py`:

1. `build_ffmpeg_args(resume=False, …)` содержит `-rtsp_transport tcp`,
   `-hls_playlist_type event`, `-hls_time <N>`, а в `hls_flags` —
   `program_date_time`, `independent_segments`, `temp_file`.
2. При `resume=False` в argv **нет** `append_list`.
3. `build_ffmpeg_args(resume=True, start_number=42, …)` содержит `append_list`
   **и** `-start_number 42`.
4. `transcode=True` → `-c:v libx264`; `transcode=False` → `-c copy`.
5. `delete_segments` не появляется ни при каких сочетаниях аргументов.
5a. **`-an` присутствует всегда** (решение D12). Проверено экспериментом: с
   аудиодорожкой камеры и `-c copy` на видео воспроизведение через MSE не
   стартует вовсе — буфер набирается, метаданные разбираются, декодируется ноль
   кадров. Без звука тот же поток играет. Тест на этот флаг обязателен: его
   отсутствие даёт молча неиграющий плеер, а это ровно тот класс дефектов,
   ради которого задача 1 вообще получила тесты.
5b. `-fflags` содержит `+genpts` и `+discardcorrupt` — камера отдаёт пакеты без
   начальных PTS, без этого муксер падает.
6. `-hls_segment_filename` указывает внутрь `out_dir` и содержит `seg_%06d.ts`.
7. `next_start_number(пустой каталог)` → `0`.
8. `next_start_number` на каталоге с `seg_000000.ts` и `seg_000007.ts` → `8`
   (максимум + 1, дыры в нумерации не мешают).
9. `next_start_number` игнорирует `index.m3u8`, `seg_000009.ts.tmp` и любые имена,
   не подходящие под шаблон.

### Дополнительно — эмпирическая проверка [A1]

**Половина [A1] уже подтверждена на реальной камере:** в выданном ffmpeg
плейлисте стоит `#EXT-X-MEDIA-SEQUENCE:0`, как и предсказывала семантика EVENT.
Документированный автоподхват `start_number` срабатывает только когда прочитанное
значение **больше** заданного, а ноль больше нуля не бывает — значит не сработает.

Осталось проверить сам перезапуск: **запустить ffmpeg дважды** с `append_list` и
без явного `-start_number` и посмотреть, перезаписался ли `seg_000000.ts`. Явный
`-start_number` остаётся в любом случае — он безвреден и корректен при обоих
исходах; изменится только обоснование.

### Вне scope

Запуск и надзор за процессом (Task 4), определение кодека (Task 3).

## Implementation

**Сделано.** `src/ingest/command.py`, тесты `tests/test_command.py` — **30 зелёных**.

Публичная поверхность:

```python
build_ffmpeg_args(*, rtsp_url, out_dir, hls_time, transcode, resume,
                  start_number: int | None = None) -> list[str]
next_start_number(out_dir: Path) -> int
resume_start_number(out_dir: Path) -> int | None   # None => дать ffmpeg решить самому
```

### Результат эмпирической проверки [A1] — допущение ОПРОВЕРГНУТО

Проверка, которую требовал этот файл, показала обратное ожидаемому:

| Случай | `append_list` один | + явный `-start_number` |
|---|---|---|
| плейлист на месте | ✅ верно | ❌ дыра в нумерации (0–3, затем 8–11) |
| плейлист потерян | ❌ затирает с нуля | ✅ верно |

`[A1]` было неверно: при живом плейлисте ffmpeg подхватывает нумерацию сам, хотя
`EXT-X-MEDIA-SEQUENCE` действительно остаётся нулём. И явный флаг оказался не
«безвредным», а вредным — он прибавляется к собственному смещению ffmpeg.

Поэтому вместо безусловного `-start_number` появилась `resume_start_number()`:
флаг ставится **только когда плейлист отсутствует**, то есть ровно в том случае,
где ffmpeg ошибается.

### Проверено на реальной камере

Argv, сгенерированный модулем, прогнан против `62.64.17.113:2554`: первый запуск
дал 6 сегментов, затем имитация падения и перезапуск с `resume=True` → 12
сегментов, `seg_000000.ts` не тронут, нумерация непрерывна, 12 записей в плейлисте.
**История DVR переживает перезапуск.**

### Отклонения от исходной спецификации

- Критерий 3 («`resume=True` содержит `-start_number 42`») переформулирован:
  флаг теперь условный. Прежняя формулировка требовала поведения, которое ломает
  нумерацию.
- Добавлена `resume_start_number()`, которой в спецификации не было.
- `-loglevel warning` и `-hide_banner` — чтобы супервизор (задача 4) читал stderr
  без баннера версии.
- При `transcode=True` добавляются `-preset veryfast` и `-g` = 10×`hls_time`,
  иначе интервал keyframe не совпадёт с длиной сегмента.
