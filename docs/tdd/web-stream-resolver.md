# Task 6 — web-stream-resolver

## Raw request

Веб-приложение на FastAPI: страница, куда можно передать путь до трансляции, и
резолвинг этого пути в URL манифеста.

## Spec

### Facts

- Проект greenfield. Python 3.14.4, тесты — `.venv/bin/pytest`.
- **ТЗ не раскрывает, что такое «путь до трансляции»** — это зафиксировано.
- Требований к аутентификации, многопользовательности и нескольким камерам в ТЗ
  нет — их и не надо изобретать.

### Decisions (связывают эту задачу)

- **D3** — FastAPI. Django рассматривался как «родной» для стека вакансии и
  отклонён: для одной страницы и одного резолвера избыточен.
- **D10** — плеер читает манифест напрямую из объектного хранилища. Веб-приложение
  **не проксирует видео**, оно только отдаёт страницу и вычисляет URL.
- **D2** — базовый публичный URL хранилища приходит из конфигурации
  (`public_base_url`), чтобы смена провайдера не трогала код.

### Assumptions

- **[A1]** `src` принимается в двух видах: как идентификатор трансляции и как
  готовый URL манифеста. ТЗ не различает, обе трактовки стоят дёшево, и поддержка
  обеих строго лучше угадывания одной.
- **[A2]** Идентификатор резолвится в `<public_base_url>/<stream_id>/index.m3u8`
  — та же раскладка ключей, что использует аплоадер (Task 5).
- **[A3]** Готовый URL возвращается без изменений, но только для схем `http`/`https`.

### Критерии готовности — чеклист, тестов не пишем

**Режим: без тестов** (решение D11). Маршруты проверяются curl'ом и открытием
страницы. Список ниже — чеклист, а не спецификация падающих тестов.

⚠️ Одно исключение стоит держать в голове: пункт 6, отклонение `../`. Это
единственная проверка здесь с оттенком безопасности. Ущерб невелик — функция
строит URL, а не читает файлы, — но если решите написать ровно один тест сверх
задач 1 и 5, писать стоит именно его.

`src/web/app.py`:

1. `GET /healthz` → 200.
2. `GET /api/resolve?src=demo` → JSON с `manifest_url`, равным
   `<public_base_url>/demo/index.m3u8`.
3. `GET /api/resolve?src=https://example.com/x/index.m3u8` → тот же URL без
   изменений.
4. `GET /api/resolve` без параметра `src` → **400**, не 500.
5. `GET /api/resolve?src=` (пустой) → 400 с внятным телом.
6. `GET /api/resolve?src=../../etc/passwd` → **400**: последовательность `..`
   отвергается как попытка обхода пути.
7. `GET /api/resolve?src=file:///etc/passwd` → 400: схема не `http`/`https`.
8. `GET /` → 200 и HTML с полем ввода.
9. `GET /watch?src=demo` → 200 и HTML.
10. Тесты не ходят в сеть и не требуют работающего хранилища.

### Вне scope

Сама логика плеера — лайв, перемотка, замер задержки (Task 7). Здесь только
маршруты, резолвинг и валидация.

## Implementation

**Сделано.** Проверено запуском — все 12 пунктов чеклиста пройдены.

Файлы:

```
src/config.py                  WebSettings / IngestSettings / UploaderSettings
src/web/resolver.py            resolve_manifest_url, InvalidSource
src/web/app.py                 create_app(settings) -> FastAPI
src/web/static/index.html      форма ввода пути
src/web/static/watch.html      страница просмотра, слот под плеер задачи 7
src/web/static/style.css       тёмная и светлая темы
```

Запуск: `PUBLIC_BASE_URL=… uvicorn --factory web.app:create_app`

### Результаты проверки

| Проверка | Ответ |
|---|---|
| `/healthz` | 200 `{"status":"ok"}` |
| `?src=demo` | 200 → `https://…/demo/index.m3u8` |
| `?src=https://ex.com/x/index.m3u8` | 200, возвращён без изменений |
| без `src` | 400 `source is empty` |
| `?src=` | 400 `source is empty` |
| `?src=../../etc/passwd` | 400 `'..' is not allowed` |
| `?src=file:///etc/passwd` | 400 `scheme 'file' is not allowed` |
| `?src=//evil.com/x` | 400 (не проходит как id) |
| `?src=a/b` | 400 (слеш запрещён) |
| `/`, `/watch?src=demo`, `/static/style.css` | 200 |

Два последних случая в спецификации не значились — добавлены при реализации:
protocol-relative адрес и слеш внутри идентификатора. Оба отсекаются тем же
правилом, что и `..`.

### Решения, принятые по ходу

- **`src/config.py` создан здесь**, хотя формально не закреплён ни за одной
  задачей. Настройки разделены по сервисам (`WebSettings`, `IngestSettings`,
  `UploaderSettings`), чтобы веб не отказывался стартовать из-за незаданного
  адреса камеры. Задачам 4, 5 и 8 останется только импортировать своё.
- **Идентификатор трансляции ограничен** `[A-Za-z0-9._-]+` плюс явный запрет
  `..`. Строго, зато однозначно: обход пути невозможен по построению, а не по
  списку запрещённых строк.
- **`create_app(settings)` — фабрика, а не глобальный `app`.** Настройки
  приходят аргументом, поэтому приложение можно поднять с любыми параметрами;
  uvicorn запускается с `--factory`.
- **Страница `/watch` резолвит манифест и кладёт его в `window.MANIFEST_URL`.**
  Задача 7 забирает адрес оттуда и ставит плеер в `#player-slot` — граница между
  задачами получилась в одну переменную.

### Подсказка со `STREAM_ID` — добавлено после вопроса «откуда берётся demo?»

Резолвер намеренно ничего не знает про то, что пишет `ingest`: он собирает
`PUBLIC_BASE_URL` + введённый путь + `index.m3u8` и на этом всё. Развязка
правильная — она и позволяет открыть чужую трансляцию по готовому адресу.

Но у неё была цена: в поле стояла подсказка `например: default`, оставшаяся от
старого значения по умолчанию, а работал на самом деле `demo` из `.env`.
Совпадение того, что пишет аплоадер, и того, что вводит зритель, ниоткуда не
следовало — ввод любого другого слова давал синтаксически корректный адрес на
несуществующий префикс и 404.

Добавлен `GET /api/default-stream` → `{"stream_id": ...}`, страница спрашивает
его при загрузке и подставляет в поле. `WebSettings.stream_id` читает ту же
переменную `STREAM_ID`, что и аплоадер, со значением по умолчанию `default`.

Развязка сохранена: это **подсказка, а не ограничение**. Любой другой путь и
любой готовый адрес манифеста по-прежнему принимаются.

### Передача камеры прямо на странице

ТЗ говорит «веб-страничка, куда можно передать **путь до трансляции**». Прочтений
два, и они дают разный объём работы:

1. путь до **сохранённой** трансляции — идентификатор или адрес манифеста;
2. путь до **источника** — адрес самой камеры, а страница её запускает.

Изначально был реализован первый: предложение в ТЗ идёт после «её сохранение в
облако», и «трансляция» в нём — то, что уже записано. Второе прочтение тоже
законно, а поддержать оба дешевле, чем спорить, поэтому поле принимает и то и
другое.

`POST /api/streams {"src": "rtsp://…"}` поднимает под камеру захват и выгрузку
внутри веб-процесса (тот же образ содержит ffmpeg) и возвращает идентификатор.

| Решение | Почему |
|---|---|
| `stream_id = "cam-" + sha256(url)[:12]` | устойчив, поэтому повторная передача той же камеры открывает ту же трансляцию, а не запускает вторую копию |
| Хэшируется **весь** URL, включая учётку | идентификатор становится префиксом в публичном бакете; пароль в нём недопустим |
| На странице показывается `scheme://host:port/path` | без учётных данных, годится и для логов |
| Потоки-демоны, ffmpeg перезапускается в цикле | в веб-процессе нет политики перезапуска Docker, а реконнекта у ffmpeg нет |
| `StreamManager` строится лениво | без ключей к бакету страница обязана открываться, а не падать |

Плеер получил прогрев: свежезапущенная камера отдаёт 404 на манифест, пока
первые сегменты не доедут до бакета. Двадцать попыток раз в три секунды, на
странице в это время «запускается…». Без этого первое же обращение к новой
камере выглядело бы как поломка.

**Аутентификации нет** — кто угодно с доступом к странице может заставить сервис
писать произвольную камеру в ваш бакет. Записано ограничением в README.

Восемнадцать тестов в `tests/test_streams.py`; критичные — на то, что пароль
камеры не попадает ни в идентификатор, ни в показываемый адрес.
