# Task 2 — ffmpeg-failure-classifier

## Raw request

Отличать по stderr ffmpeg отказ аутентификации от сетевого отказа, чтобы
диагностика §7 была возможна, а супервизор не долбил камеру с заведомо неверным
паролем.

## Spec

### Facts

- Проект greenfield. Python 3.14.4, тесты — `.venv/bin/pytest`.
- Требование родилось из находки критика: строка «Логи должны отличать сеть от 401»
  стояла в разделе Data flow, но **ни один компонент ею не владел**.
- Реальный контекст, делающий это не теоретическим: креды камеры из §7 при проверке
  были отвергнуты (`401 Unauthorized`, `Digest realm="IP Camera(FU157)"`), при том
  что TCP-порт открыт и RTSP `OPTIONS` отвечает `200 OK`. То есть «сеть жива, но
  аутентификация не проходит» — реально наблюдавшееся состояние, а не выдумка.

### Decisions (связывают эту задачу)

- **D1** — RTSP-источник параметризуется, камера может быть недоступна или
  отвергать креды в любой момент. Классификация — то, что делает это отличимым
  в логах.

### Assumptions

- **[A1]** ffmpeg печатает диагностику в stderr текстом, содержащим узнаваемые
  подстроки (`401`, `Unauthorized`, `Connection refused`, `Connection timed out`,
  `No route to host`). Классификатор работает по подстрокам, а не по кодам выхода:
  ffmpeg возвращает ненулевой код почти на всё подряд, и он неинформативен.
- **[A2]** Классификатор получает **хвост** stderr (последние N строк), а не весь
  вывод целиком — полный лог может быть большим.

### Критерии готовности — чеклист, тестов не пишем

**Режим: без тестов** (решение D11). Это регексп по строке: дефект виден сразу,
а мок ничего не добавляет. Проверяется вызовом функции в REPL или по логам при
первом обрыве. Список ниже — чеклист, а не спецификация падающих тестов.

`src/ingest/failures.py`:

1. Есть `FailureKind` со значениями `AUTH`, `NETWORK`, `CODEC`, `UNKNOWN`.
2. Текст с `401 Unauthorized` → `AUTH`.
3. Текст с `Connection refused` → `NETWORK`.
4. Текст с `Connection timed out` → `NETWORK`.
5. Текст с `No route to host` → `NETWORK`.
6. Пустая строка → `UNKNOWN`, **без исключения**.
7. Незнакомый текст → `UNKNOWN`, **без исключения**.
8. Регистр не влияет: `unauthorized`, `UNAUTHORIZED`, `Unauthorized` дают `AUTH`.
9. Обрамляющий шум лога не мешает: многострочный вывод ffmpeg с баннером версии,
   где искомая строка в середине, классифицируется правильно.
10. Если в тексте есть признаки и `AUTH`, и `NETWORK`, побеждает `AUTH` —
    неверные креды повтором не лечатся, и это важнее для диагностики.

### Вне scope

Реакция супервизора на класс отказа — backoff и логирование (Task 4). Здесь только
чистая функция от текста.
